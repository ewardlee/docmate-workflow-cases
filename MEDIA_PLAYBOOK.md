# DocMate Media Playbook

## One story, many surfaces

Do not invent a new campaign for every platform. Build one canonical case and translate it into the native language of each medium.

## Short video — TikTok / Reels / YouTube Shorts

**Goal:** emotional recognition + one proof moment  
**Length:** 20–35 seconds  
**Format:** 9:16  
**Structure:** human hook → risk → real DocMate UI → resolved outcome

Rules:
- Put the conflict in the first 2–3 seconds.
- Do not start with a logo animation.
- Use AI-generated actors/locations only for narrative context.
- Cut to authentic DocMate capture for every product claim.
- Keep visible product copy large enough for a phone screen.
- One video = one problem.

## YouTube proof video

**Goal:** turn curiosity into trust  
**Length:** 45–90 seconds

Structure:
1. 10–20 second theatre opening.
2. State the exact task.
3. Show the synthetic input documents.
4. Run the real DocMate workflow.
5. Show the output / version / record that remains.
6. Mention limitations honestly.

A reviewer should be able to download the same fixtures from this repository and reproduce the case.

## Instagram carousel

Recommended 6 frames:
1. Problem
2. What the user was told
3. What actually changed
4. Source page
5. Action taken
6. Final record / CTA

Avoid ten-feature grids.

## LinkedIn

Write from the business outcome, not the app feature.

Example angle:
> A revised supplier PDF does not need to look dramatically different to create a real operational risk. One number, date, or payment term is enough.

Then explain:
- what changed
- why it matters operationally
- how a version-aware workflow helps
- transparent disclosure that DocMate is the product being built

Best audiences:
- procurement
- finance
- operations
- consultants
- property management
- compliance

## Reddit

Reddit is **not an ad-placement channel**.

Use the story to teach or discuss a real workflow.

Rules:
- Read and obey each subreddit's self-promotion rules.
- Never pretend to be an independent user.
- Disclose: "I build DocMate."
- Do not manufacture testimonials.
- Lead with the problem or reproducible documents, not a download link.
- Be useful even if the reader never installs DocMate.
- When allowed, link to this GitHub case before linking to a store page.

Good format:
1. "I noticed people solve X by doing Y manually."
2. Explain the failure mode.
3. Share synthetic example documents.
4. Explain what a safer workflow needs.
5. Ask the community what they would want recorded.
6. Disclosure at the end.

## GitHub

GitHub is the **evidence layer**.

Each case should contain:
- fictional source documents
- exact expected changes
- workflow description
- product screenshots/GIFs when captured
- limitations
- a media script

This lets:
- reviewers reproduce claims
- journalists inspect examples
- developers discuss workflow design
- users understand the product without marketing language

Never upload:
- proprietary DocMate source
- real customer data
- App Store credentials
- private analytics
- real contracts or personal documents

## App Store Custom Product Pages

Each CPP should represent a job, not a feature bundle.

Examples:
- **Contract / Lease:** Before you sign, see what changed.
- **Scan / Restore:** Restore documents, not just scan them.
- **Private document intelligence:** Understand important facts with evidence.
- **Life admin:** Keep documents, deadlines, and history together.

## Threads / Facebook

Use short story posts:
- first sentence = situation
- second = hidden problem
- third = what DocMate revealed
- one real product clip or screenshot

## Journalist / reviewer outreach

Do not send "DocMate has 30 features."

Send one reproducible challenge:

> Here are two fictional lease PDFs. Five things changed, including one change that is easy to miss. The same files are public in the GitHub case. If you want, run them through the TestFlight build and see whether the workflow earns the claim.

That is substantially more credible than a feature sheet.

# Production rule

> **AI = emotion and context. Real DocMate = evidence.**

AI can generate:
- actor
- room
- office
- phone-message setup
- lighting
- reaction shot
- paper environment
- establishing shot

AI must not fabricate:
- DocMate app screen
- Compare result
- OCR output
- saved signature
- fingerprint status
- success state
- App Store rating
- customer testimonial

## Asset naming

Use:

`STORY##_slug_scene##_type.ext`

Examples:
- `STORY01_lease_scene01_message.mp4`
- `STORY01_lease_scene04_real_compare.mov`
- `STORY01_lease_cover_9x16.png`

## Proof metadata

For any published real product capture, retain:
- DocMate version/build
- source fixture identifiers
- capture device
- capture date
- SHA-256 of input fixtures where practical
- statement of what the clip actually proves

The objective is creative marketing with an auditable truth layer.
